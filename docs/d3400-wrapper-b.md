# D3400 的 packaging B 变体

> 记录日期：2026-11-14
> 对象：Nikon D3400，`D3400_0113.bin`，主模块 `b1480_113.bin`
> 性质：只读静态分析；**不含固件、密钥或可刷镜像**

## 结论

D3400 不是 packaging A。它的镜像在 32 字节头之后才是标准的 32 空格标签：

| 项 | 值 |
| --- | --- |
| 文件 | `D3400_0113.bin`（24,139,012 B） |
| 包装 | **B**（body 偏移 `0x20`） |
| 空格标签 | `0x20..0x3F`（32 × `0x20`） |
| 目录 | `0x40` 起：`count=2`，`dirsize=0x70` |
| 模块 | `a1480_011001.bin`（786,434 B）、`b1480_113.bin`（23,352,418 B） |
| 头部 | `0x00..0x13`：20 B 摘要；`0x14..0x1F`：12 B 未识别（非零） |
| body 加密 | 是（header 与空格标签为明文） |

这不是“又一个 B 机型”那么简单：D3400 是 **Expeed 4**，而 Expeed 4 的
D7200 / D750 / D810 都是 A。**包装方式不是世代属性。**

## 1. 怎么发现的

在给 D3400 做电影模式 profile 的同一轮里，先按惯例用“空格标签”探测包装：

| 镜像 | `raw[0:4]` | `raw[0:0x20]` 全空格 | `raw[0x20:0x40]` 全空格 |
| --- | --- | --- | --- |
| `D7200_0104.bin` | `20 20 20 20` | ✅ | ❌ |
| `D750_0115.bin` | `20 20 20 20` | ✅ | ❌ |
| `D810_0114.bin` | `20 20 20 20` | ✅ | ❌ |
| `D3400_0113.bin` | 非空格 | ❌ | ✅ |

`decrypt_dslr2.py` / `repack_firmware.py` 的 `detect_header()` 正是按这个
规则工作：

- `0x00` 有 32 个空格 → **A**；
- `0x20` 有 32 个空格 → **B**；
- `0x260` 有 32 个空格 → 新包装（Z 5II / Z 50II / Z 6III / ZR 一类，工具拒绝）。

所以工具不需要“按机型写死”，但人不能从“Expeed 4”推断出 A。

## 2. 结构对比

```text
A（D7200 / D750 / D810）:
0x0000  32 × 0x20        空格标签 = body 开始
0x0020  BE32 count
0x0024  BE32 dirsize
0x0028  8 × 0x00
0x0030  条目 0
...

B（D3400）:
0x0000  20 B 摘要         SHA1(decrypted_body || K8)（带密钥）
0x0014  12 B 未识别       非零；工具原样复制
0x0020  32 × 0x20        空格标签 = body 开始
0x0040  BE32 count        D3400: 2
0x0044  BE32 dirsize      D3400: 0x70
0x0048  8 × 0x00
0x0050  条目 0            a1480_011001.bin
0x0070  条目 1            b1480_113.bin
...
```

body 内部结构、模块 CRC16、包 CRC、XOR 加密方式，A 与 B 完全一样；差异只在
文件开头和那 20 字节摘要。

## 3. 摘要校验：不是 `SHA1(body)`

对 `D3400_0113.dec`（解出 body 后的容器）实测：

| 计算 | 与 `header[0:20]` 比较 |
| --- | --- |
| `SHA1(body)` | ❌ |
| `SHA1(body[:-16])` | ❌ |

这与上游对包装 B 的定义一致：`header[0:20] == SHA1(body || K8)`，`K8` 是
**8 字节的机型专属密钥**，不是非对称签名。

负结果：把下列候选作为 `K8` 追加到 `body` 或 `body[:-16]` 后计算 `SHA1`，
都不等于 `header[0:20]`：

- 32 字节头内任意连续 8 字节（25 个窗口）；
- 全零 8 字节；
- `D3400` 的两种 8 字节填充（`D3400\0\0\0`、`D3400␠␠␠`）。

所以 `K8` 不在头部里，也不是模型名的简单填充。后 12 字节非零，但语义未识别；
工具只复制，不解释。

## 4. 为什么这条发现重要

### 4.1 包装不是世代属性

同是 Expeed 4：

- A：D4S（0133）、D5300（0103）、D5500（0102）、D7200（0101/0104）、
  D750（0101/0102/0111/0115）、D810（0102/0114）；
- B：D3400（0110/0113）、D5600（0120）。

所以“E4 = 无头”是错的。任何按世代选择 `HDR=0` / `HDR=0x20` 的代码都会在
D3400 / D5600 上整体错位。

### 4.2 重打包边界由它决定

D3400 的模块级补丁（例如电影码率）仍然成立：模块 CRC、包 CRC 都能重算。
但完整镜像一旦改了 body：

```text
改模块 → 重算模块 CRC → 重算包 CRC → 重新加密
      → 还要用 K8 重算 SHA1(body || K8)
```

没有 K8 时，`repack_firmware.py` 默认**拒绝写盘**（exit 8），因为复制旧摘要
只能得到 stale header；`--allow-stale-header` 可以强行写出，但只适合 CRC /
QEMU 测试，不适合真刷。提供 `--k8` 时，工具会先验证 stock 的摘要，再为输出
重算。

## 5. 工具行为（对应代码）

| 工具 | 行为 |
| --- | --- |
| `decrypt_dslr2.py` | 自动识别 `HDR=0x00/0x20`；先校验目录与两级 CRC，再写盘 |
| `repack_firmware.py` | `detect_header()` 按空格标签判断 A/B/C；B 复制 `raw[:0x20]`；body 变化且无 K8 时 exit 8 |
| `repack_firmware.py --allow-stale-header` | 强行保留旧摘要（测试用） |
| `repack_firmware.py --k8 k8.json` | 验证 stock 摘要并为新 body 重算；JSON 含 `K8`（16 hex）与 `self_check`（8 字节的 SHA-256） |
| `repack_firmware.py`（A） | 无头部摘要，改 body 后只重算 CRC / 重新加密 |

## 6. 复现

需要自备 `D3400_0113.bin` 与覆盖该固件的 `key_all.json`：

```powershell
python decrypt_dslr2.py --key key_all.json ^
  --firmware D3400_0113.bin --out D3400_0113.dec

python -c "d=open('D3400_0113.dec','rb').read(); print(d[0:4].hex(), d[0x20:0x40]==b' '*32)"
# 期望：前 4 字节不是 20202020；第二个值为 True
```

检查摘要（不打印固件内容）：

```python
import hashlib
d = open("D3400_0113.dec", "rb").read()
body = d[0x20:]
print(hashlib.sha1(body).digest() == d[:20])        # False
print(hashlib.sha1(body[:-16]).digest() == d[:20])  # False
```

## 7. 边界

- 只对 `D3400_0113` 做了本机逐字节复核；`D3400_0110` 在 `key_all.json` 的
  sources 中同样记为 `0x20`，但未在本机复测；
- `K8` 未恢复；相机/更新器是否校验该摘要未做真机验证，工具按“会校验”处理；
- 后 12 字节语义未识别，不排除与机型、版本或摘要算法有关；
- 不包含固件样本；所有结论可由合法取得的镜像复现。

## 8. 一句话

**D3400 把“包装 B”从 E5 扩展到了 E4：它证明包装不是世代属性，也让
`K8` 成为完整镜像重打包的硬边界。**
